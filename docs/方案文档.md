# 学生错题集系统 · 方案文档

> 版本：v1.1　日期：2026-10-08
> 目标：为家中学生搭建一套错题管理网页，支持 PDF 试卷录入、错题标记、分类归纳、自动组卷打印、知识点薄弱分析。

---

## 1. 需求分析

### 1.1 用户与场景

- **主要用户**：家长（录入、整理、组卷打印）、学生（做错题卷、看解析）。
- **典型场景**：
  1. 考试/练习后发下试卷（PDF 电子版或扫描件），家长上传，系统自动切分题目，勾选错题入库。
  2. 日常作业中做错的题，手动逐题录入。
  3. 周末/考前，按「年级 + 学期 + 科目 + 知识点」筛选错题，随机抽题生成练习卷，打印给孩子重做。
  4. 定期查看知识点掌握分析，找出薄弱环节，针对性出题强化。

### 1.2 功能需求清单

| 编号 | 功能 | 优先级 | 说明 |
| --- | --- | --- | --- |
| F1 | PDF 上传与题目自动切分 | P0 | 文本型 PDF 直接解析；扫描件走 OCR |
| F2 | 手动录入题目 | P0 | 文本 + 图片混排 |
| F3 | 错题标记与分类 | P0 | 年级、上下学期、科目、知识点标签 |
| F4 | 错题集浏览与筛选 | P0 | 多维组合筛选、搜索、掌握状态跟踪 |
| F5 | 自动抽题组卷、打印 | P0 | 随机/按薄弱点抽题，生成可打印文档 |
| F6 | 知识点薄弱分析 | P1 | 错题按知识点聚类统计，可视化 |
| F7 | 按知识点出题 | P1 | 从题库抽同类题 / AI 生成同类练习题 |
| F8 | 复习提醒（遗忘曲线） | P2 | 艾宾浩斯曲线推送复习 |
| F9 | 多孩子/多用户管理 | P2 | 家庭内多个学生数据隔离 |

### 2.3 调研结论

- **若要最快落地**：直接部署 `wrong-notebook`（Docker 一条命令），已覆盖 F3/F4/F5/F6/F7 的大部分；缺的「整卷 PDF 自动切分」可借鉴 `Fuck-wrong-question` 的 MinerU 方案补上。

## 4. 关键流程设计

### 4.1 PDF 录入流水线

1. 上传 PDF → 判断类型：能否提取出文本层。
2. **文本型 PDF**：pdf.js/PyMuPDF 提取全文 → 按题号正则切分（兼容 `1.`、`1、` `(1)`、`第1题` 等格式）→ 预览列表 → 人工校对、勾选错题、设年级/学期/科目 → 入库。
3. **扫描件 PDF**：转图片 → OCR（PaddleOCR/Umi-OCR）或 AI 多模态识别 → 切题 → 同上人工校对。
4. AI 后处理（可选）：自动补全答案解析、自动打知识点标签（对标 wrong-notebook）。

> 本次 demo 已实现第 2 步的纯前端版本；OCR 与 AI 打标属正式版迭代内容。

### 4.2 组卷与打印

- 抽题策略：按筛选条件（年级/学期/科目/知识点/掌握状态）随机抽 N 题；支持「薄弱知识点加权」——知识点错误次数越多，该知识点的题被抽中概率越高。
- 输出：打印友好的试卷页（卷头含姓名/日期/得分栏，题间留答题空白），可选另起一页附答案解析；同时可导出 Word/PDF。

### 4.3 知识点薄弱分析

- 统计口径：错题数按知识点聚合，结合「掌握状态」与「最近复习时间」计算薄弱指数。
- 展示：知识点 × 错误次数横向条形图（demo 已含）；正式版可加时间趋势、科目分布饼图。
- 闭环：点击薄弱知识点 → 一键抽该知识点的错题组卷 → 孩子重做 → 更新掌握状态 → 分析数据随之更新。

## 7. AI 接入（M3，已完成）

### 7.1 架构

新增轻量代理后端 `server/`（FastAPI），浏览器不直连 AI 厂商，密钥只存在服务端 `config.json`（权限 600，已 gitignore）。`main.py` 用 StaticFiles 把 `demo/` 托管在 `/`，前后端同源，同时保留 CORS 中间件供独立部署前端时使用。

### 7.2 支持的厂商（OpenAI 兼容接口）

| 厂商 | base_url | 预设模型 |
| --- | --- | --- |
| GLM 智谱 | https://open.bigmodel.cn/api/paas/v4 | glm-4-flash / glm-4-air |
| DeepSeek | https://api.deepseek.com/v1 | deepseek-chat |
| Kimi 月之暗面 | https://api.moonshot.cn/v1 | moonshot-v1-8k / kimi-k2-0905-preview |
| MiniMax | https://api.minimaxi.com/v1 | MiniMax-M1（备选 abab6.5s-chat） |
| Qwen 阿里 | https://dashscope.aliyuncs.com/compatible-mode/v1 | qwen-turbo / qwen-plus |
| 自定义 | 任意 OpenAI 兼容接口 | 手填 |
| Mock | 无 | 内置假数据，无需 Key，离线联调用 |

### 7.3 四类 AI 能力与 Prompt 约束策略

| 能力 | 接口 | Prompt 约束 |
| --- | --- | --- |
| 知识点打标 | POST /api/ai/tag | 注入该「年级×学期×科目」的知识点目录（`catalog.json`，预置小学语数英 1-6 年级上下学期 + 初中数学主干，每条约 10-20 个），要求优先从目录选取并标 `custom:false`，目录外补充标 `custom:true`，最多 5 个，强制纯 JSON 输出 |
| 答案/解析生成 | POST /api/ai/solve | 要求答案简洁准确、解析给关键步骤，输出 `{"answer","explanation"}` |
| 同类题生成 | POST /api/ai/similar | 原题+知识点+数量，要求变式不照抄、每题附答案，输出 `{"questions":[…]}` |
| 整卷切分校对 | POST /api/ai/split-check | 输入切分后的题目数组，要求合并误切/拆出漏切/剔除页眉页脚并标注题型，保持原文不改写 |

统一策略：system 强制「只输出 JSON」；后端先正常解析，失败则正则兜底提取（剥 ` ```json ` 围栏 → 截取配对花括号）；再按任务做字段校验。错误区分四类返回：`config_error`（未配置 Key）、`auth_error`（401/403）、`network_error`（连接厂商失败）、`output_error`（输出无法解析）。

### 7.4 前端 AI 能力层

前端存储仍是 localStorage，AI 仅作为增强层：顶栏「AI 设置」面板（厂商/base_url/模型/Key 存取、Key 打码回显、测试连接）；PDF 导入预览提供「AI 校对切分」「全部 AI 打标」（逐题带进度）并补上知识点编辑框（修复导入后知识点恒为空的问题）；手动录入支持「AI 打标」「AI 生成答案解析」；错题卡片「生成同类题」弹层勾选入库（isWrong=false、继承知识点）；知识点分析每行「AI 出题」生成 5 道同类题，可加入题库或直接组卷打印。统一 `callAI()` 封装 loading 态与错误 toast。

- OCR（M2）：扫描件 PDF 目前仍提示仅支持文本型 PDF，待接入 PaddleOCR/Umi-OCR 或 AI 多模态。
- 真实厂商端到端验证：需用户自填 Key 后用「AI 设置 → 测试连接」验证。

## 8. 数据落库（M1，已完成）

- 存储从浏览器 localStorage 迁移到本地 SQLite（Python 标准库 sqlite3，无 ORM）。
- 数据库文件固定在用户目录 `~/.cuotiji/cuotiji.db`（Windows 为 `C:\Users\xxx\.cuotiji\`），因为打包后的 exe/app 可能位于只读目录；运行日志 `app.log` 同目录。
- 表结构对齐前端数据模型：`questions(id TEXT 主键, text, answer, grade, term, subject, knowledge_points JSON数组字符串, is_wrong INTEGER, wrong_reason, mastery, source_file, created_at)`。
- REST API：`GET /api/questions`（grade/term/subject/kp/mastery/onlyWrong/keyword 服务端组合筛选）、`POST /api/questions`（单个或数组批量插入，服务端规范化）、`PUT /api/questions/{id}`、`DELETE /api/questions/{id}`、`GET /api/export`、`POST /api/import`（全量替换，覆盖确认由前端做）。
- 前端 storage.js 改为 fetch 封装的远程 store（内存缓存保持同步读接口），首次启动自动把旧 localStorage 数据迁移入库并提示；后端不可达时显示引导页（不再支持 file:// 双击）。

## 9. 本地安装包（M1.5，已完成）

- `launcher.py`：桌面入口——bind 端口 0 探测空闲端口、线程内启动 uvicorn（log 写 `~/.cuotiji/app.log`）、服务就绪探测后自动 `webbrowser.open`。

## 10. Tauri 2 壳改造（M1.6，已完成）

### 10.1 架构

```
┌────────────────────────────────────────────┐
│  Tauri 2 壳（Rust，仅壳职责）                │
│  bind 0 探测端口 → spawn python-server       │
│  sidecar(--port N) → 轮询 /healthz →         │
│  WebView navigate http://127.0.0.1:N/        │
│  退出时 kill sidecar                          │
└──────────────────┬─────────────────────────┘
                   │ --port N
┌──────────────────▼─────────────────────────┐
│  python-server sidecar（PyInstaller onefile）│
│  = launcher.py + server/（FastAPI+SQLite+AI） │
│  托管 demo/ 前端，数据在 ~/.cuotiji/         │
└────────────────────────────────────────────┘
```

Rust 只承担壳职责，业务逻辑零重写；demo/ 前端不改，仍由 FastAPI 托管。

### 10.2 要点

- `launcher.py` 双模式：无参数为开发者模式（自探端口 + 开浏览器）；`--port N` 为 sidecar 模式（Tauri 传入，不自探、不开浏览器）。
- `server/main.py` 新增 `GET /healthz` 健康检查，供壳做就绪探测。
- `cuotiji.spec` 输出名 `python-server`，构建脚本把产物复制为 `python-server-<target-triple>[.exe]` 放入 `src-tauri/binaries/`（gitignored），Tauri `externalBin` 嵌入。
- `src-tauri/`：tauri 2 依赖从简（不引插件）；`tauri.conf.json` 主窗口 1200×800、标题「错题集」、背景色 `#f4f6fa` 防白闪、identifier `com.stevesunyifan.error-notebook`；`sidecar.rs` 就绪轮询 5s 间隔 / 60s 超时，超时窗口显示错误页（附 `~/.cuotiji/app.log` 路径）；capabilities 最小权限（core:default）。
- 构建：`build_macos.sh`（PyInstaller sidecar → cargo tauri build → .app + .dmg）、`build_windows.bat`（→ NSIS .exe）；`.github/workflows/build.yml` push `v*` tag 双平台构建（PyInstaller → tauri-action@v0 → 上传 .dmg / .exe artifact）。
