## 三、测试中发现的问题

### D1 大学旧数据迁移未命中（已修复 ✅）

| 项 | 内容 |
| --- | --- |
| 现象 | 迁移 SQL 条件 `WHERE stage='大学' AND grade IN (旧课程名)`；但旧数据经回填逻辑后 stage='其他'（回填只识别 K12 年级），条件不命中，旧大学错题保持 `grade=高等数学` 原样 |
| 复现 | 构造空 stage 旧库，grade='高等数学' → 迁移后未变更 |
| 修复 | 改为按课程名匹配（`WHERE grade IN (...)`），同时置 `stage='大学'`（`db.rs` migrate） |
| 复验 | 修复后迁移正确：`grade=公共基础, stage=大学`；cargo test 13/13、clippy 0 |
| 教训 | 迁移条件不能依赖被回填逻辑改写过的字段；回填与改名有依赖序 |

### 用例设计修正 2 项（非缺陷）

| 用例 | 原预期 | 修正后 | 依据 |
| --- | --- | --- | --- |
| tag 缺字段校验 | `{"question":"t"}` 应 422 | 仅缺 `question`（传 `{}`）才 422；传了 question 即合法 200 | pydantic TagIn：question 必填，grade/term/subject 均有默认值 |
| Key 打码格式 | `bad-****5678` | `bad****5678`（前 3 + **** + 后 4，无连字符） | providers.rs mask_key 实现一致即可，格式本身无标准 |
